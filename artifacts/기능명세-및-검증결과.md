# 티라니 모바일 청첩장 · 기능 명세와 검증 결과

기준: 2026-11-02, 로컬 데모. 실제 판매 서비스가 아닌 개발 단계다.

## 관리자

- 사이드탭: 템플릿, 회원, 결제 내역, 추천 정책, 추천·정산, 활동 로그, 알림 발송, 이메일 템플릿.
- 추천 정책은 할인율과 적립률을 각각 0~100 정수 퍼센트로 입력해 새 버전을 생성한다. 이전 버전과 결제 당시 정책 ID는 유지한다. 최신 활성 정책은 이후 결제에 적용한다.
- 추천 결제 목록에 구매자 이메일, 추천인, 결제액, 할인, 적립과 정책을 표시한다. 포인트 원장과 기프티콘 신청 내역도 본다.
- 모의 결제의 전체·부분 환불을 기록한다. 부분 환불 비율에 따라 추천 포인트를 회수하고 구매에 쓴 포인트를 반환한다. 이미 포인트를 사용한 후 회수하면 잔액이 음수가 될 수 있다.
- 전체 회원 또는 특정 회원에게 앱 내 알림을 발송할 수 있다. 활동 로그는 로컬 데모 기록이며 DB 및 Mixpanel은 아직 연결되지 않았다.
- HTML/CSS 템플릿과 이메일 템플릿을 편집한다. 이메일 발송은 미연결이다.

## 유저 — 청첩장을 만드는 사람

- 템플릿 링크나 본인 추천 링크를 복사해 공유할 수 있다. 추천 링크는 브라우저 탭의 세션 저장소에 보관되고, 추천받은 유저의 결제에서 활성 정책을 적용한다. 자기 추천은 적용하지 않는다.
- 비회원도 기본 정보를 입력해 실시간으로 미리 볼 수 있다. 작성 내용은 해당 브라우저 탭에 임시 저장되며 로그인 후 본인 청첩장으로 가져온다. 사진 추가는 로그인 후 이용 가능하다. 브라우저 탭을 닫거나 사이트 데이터를 지우면 임시 데이터가 사라질 수 있다.
- 편집 후 모의 결제와 발행을 할 수 있다. 추천 할인은 템플릿 정가에 적용하고, 보유 포인트는 할인 후 가격까지 사용할 수 있다. 추천 포인트는 포인트 차감 후 실제 모의 결제액 기준으로 계산하며 각 금액은 원 단위에서 내림한다. 실제 결제가 아니다.
- 추천 대시보드에서 포인트 잔액, 추천 결제자의 이메일·결제액·적립 내역, 포인트 사용·환불 내역과 기프티콘 신청 상태를 확인한다.
- 카카오 또는 Tremendous 기프티콘을 신청하면 포인트가 예약되고 연동 대기 상태가 된다. **실제 기프티콘 발송과 예약 취소는 구현되지 않았다.**
- 앱 내 알림을 읽고 확인 처리한다. 채널톡 고객 상담은 연결 준비 중이다.

## 하객 — 청첩장을 받는 사람

- 발행된 링크로 청첩장과 사진, 예식 정보, 방명록을 볼 수 있다. 청첩장을 공유할 수 있으며, 청첩장 하단에서 템플릿 목록으로 이동할 수 있다.
- 목록용 사진은 축소 WebP를 사용하고 확대할 때 원본을 요청한다.
- HTML 템플릿은 격리된 프레임에서 보이며 사진 슬롯과 일부 공유 UI는 아직 미구현이다.

## 테스트 결과

- `npm run build`: 통과.
- `npm test`: 7개 통과. 청첩장 소유자 분리·템플릿 스냅샷, 결제와 발행 조건, 추천 할인·적립 및 부분 환불, 자기 추천, 포인트 초과, 정책 버전, 기프티콘 예약을 검증했다.
- Playwright: `tests/e2e/platform.spec.ts`와 `playwright.config.ts`에 재사용 가능한 화면별 테스트·캡처 스크립트를 작성했다. 고정 대기와 waitFor 계열 호출은 사용하지 않았다. 실제 실행은 이 환경의 로컬 포트 바인딩 `EPERM`으로 개발 서버 시작이 실패하여 중단됐고, 화면 캡처 파일은 생성되지 않았다. 준비된 환경에서 `npm install`, `npx playwright install chromium`, `npm run test:e2e`로 실행한다. 결과는 `artifacts/screenshots/`에 저장하도록 설정했다.

## 공통 미구현과 운영 전 작업

- 로컬 JSON 저장소만 동작한다. PostgreSQL/Prisma 어댑터, 마이그레이션, Supabase 연동은 미완성이다. 로컬 JSON은 다중 프로세스 트랜잭션을 보장하지 않는다.
- 실제 PG 결제/환불, 빌링키 암호화 처리, 소셜 로그인, 이메일 인증 및 발송, 기프티콘 API, 채널톡, DB 로그/Mixpanel은 미연결이다. 관련 스키마나 인터페이스가 있다고 해서 외부 연결이 완성된 것은 아니다.
- 실제 서비스에 필요한 추천 기여 기간과 중복 귀속, 악용 방지, 개인정보 제공 범위, 환불·포인트 정책, 기프티콘 전송·실패 복구·취소는 확정과 구현이 필요하다. 현재 추천 코드는 데모용 사용자 ID이고 세션 단위로 보존된다.
- GitHub 접근 실패 및 Docker 데몬 미연결로 원격 반영과 DB 실행은 확인하지 못했다. 실제 고객 정보나 금전을 처리하지 않는다.
